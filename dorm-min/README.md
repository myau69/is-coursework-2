# Общежитие — база данных в PostgreSQL

Семь сервисов — семь баз. У каждой базы своя папка с четырьмя файлами:

| Файл | Что внутри |
|---|---|
| `up.sql` | создание таблиц и индексов |
| `functions.sql` | триггеры |
| `seed.sql` | тестовые данные (INSERT) |
| `down.sql` | удаление всего, что создали `up.sql` и `functions.sql` |

Порядок запуска для одной базы: `up` → `functions` → `seed`. Чтобы начать заново: `down`, потом снова по порядку.

Всё сразу для всех баз:

```bash
./scripts/db.sh reset   # down + up + seed
./scripts/db.sh up      # создать базы (если нет), таблицы, индексы, триггеры
./scripts/db.sh seed    # залить тестовые данные
./scripts/db.sh down    # удалить таблицы и триггеры (сами базы остаются)
```

Запуск на macOS — в [RUN_MACOS.md](RUN_MACOS.md).

## Базы

- `dorm_identity` — пользователи, жилые комнаты, права
- `dorm_booking` — бронирование переговорок по слотам
- `dorm_gym` — допуск в спортзал
- `dorm_laundry` — прачечная
- `dorm_notification` — объявления, оплата проживания, уведомления
- `dorm_office` — кабинеты и живая очередь
- `dorm_study` — учебные комнаты

Колонки вроде `user_id`, `author_id`, `residential_room_id` ссылаются на данные из другой базы
(обычно `dorm_identity`). `FOREIGN KEY` между разными базами сделать нельзя, поэтому это
обычные числа, а их правильность проверяет приложение.

Для скриншотов индексов и триггеров в отчёт: открыть в pgAdmin Query Tool нужной базы
`scripts/report_indexes.sql` или `scripts/report_triggers.sql` и нажать F5.
